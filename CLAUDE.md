## What this is
A multi-user blog platform: anyone can browse and read published posts without logging in;
registered users write and manage their own posts; other logged-in users like and comment.
Week 1: core blog + auth. Week 2 (v2): import/export + performance. Week 3 (v3): social login, sessions, publications as tenants.
Week 4 (v4): permission-based RBAC, moderation, audit log; Docker, CI/CD, health, logs, metrics, error tracking, backups.
v5: MVC layering with repositories, REST API v2 (posts/comments/likes), third-party integrations (Anthropic, Dev.to, GitHub), explicit engineering workflow.
Deliverable is a production-quality repo that runs locally with a prod-like compose stack — not a cloud deployment.

## Commands (run from repo root)
These targets do not exist until T-001. Create them exactly as named.
- First-time setup: `cp .env.example .env && make up && make migrate && make seed`
- Run everything: `make up` (docker compose: db :5432, redis :6379, api :8000, worker, web :5173)
- With S3-compatible storage: `make up-s3` (adds MinIO :9000/:9001, sets STORAGE_BACKEND=s3)
- Stop: `make down`
- Apply migrations: `make migrate` · New migration: `make migration m="message"`
- Seed demo data: `make seed` (idempotent) · Perf dataset: `make seed-perf` (100k posts — slow, run once)
- Query plans: `make explain` (EXPLAIN (ANALYZE, BUFFERS) for the key queries → docs/perf/plans/)
- Load test: `make loadtest` (Locust, headless, 60 s) · Worker logs: `make logs-worker`
- Backend tests: `make test-api` · Frontend tests: `make test-web`
- Lint / format: `make lint` · `make fmt` · All CI checks locally: `make ci`
- Prod-like stack: `make up-prod` (built images, nginx on :8080, no bind mounts, db/redis not exposed)
- Observability: `make up-obs` (Prometheus :9090, Grafana :3000, GlitchTip :8001)
- Backups: `make backup` · Restore drill: `make restore-test` · Admin bootstrap: `make grant-admin email=...`
- Regenerate permission docs: `make permissions-doc` · Regenerate typed API client: `make gen-client`
- Architecture boundaries: `make lint-arch` (import-linter; also part of `make lint`) · Webhook tunnel: `make smee`
- List every target: `make help`
- Live API docs: http://localhost:8000/docs (OpenAPI generated by FastAPI)

## Session protocol
1. Start: read `docs/tasks.md`. Continue the IN PROGRESS item; if none, take the top TODO.
2. One task per session where possible. A task is DONE only when its acceptance criterion is met
   AND `make test-api` and `make lint` pass. Say which command you ran and its result.
3. Before any change touching >3 files, any schema change, or any new dependency: state the plan, wait for approval.
4. If a rule in `docs/rules.md` conflicts with a request, flag it — do not silently pick one.
5. Performance work: measure first (`make explain` / `make loadtest`), change one thing, measure again, record both in docs/performance.md. No optimisation without a before/after number.
5b. Layers: routers → services → repositories only; no SQL outside repositories; no `fastapi` imports in services; outbound HTTP only via `app/integrations/http.py`.
6. Authorisation: check permissions via `app/authz/` only — never compare role names in routes, services or the frontend.
7. If a request falls under "Explicitly out of scope" in `docs/product.md`, say so and stop, however small it looks.
8. End: update `docs/tasks.md` status; append any new decision or gotcha to `docs/memory.md`; show the diff.
